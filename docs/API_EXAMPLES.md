# API examples (real responses)

> Generated by `scripts/make_api_examples.py` from a running server on the SIMULATED 20-cell sample. Interactive docs: `http://localhost:8000/docs`. Long lists are shortened.

Every request needs **at least N consecutive 5-minute readings per cell** (N is `history_required_steps` from `/model/info`; 73 for the hybrid). Send `null` for a failed sensor value, never an impossible number.

## GET /health

```bash
curl localhost:8000/health
```


Response (HTTP 200):

```json
{
  "status": "ok",
  "model_loaded": true,
  "model": "hybrid",
  "version": "1.0.0",
  "uptime_seconds": 14.8,
  "alert_channels": [
    "log"
  ],
  "problem": null,
  "data_note": "Prototype trained on SIMULATED data."
}
```

## POST /readings  (streaming mode, buffer only)

```bash
curl -X POST localhost:8000/readings -H 'Content-Type: application/json' -d '{"readings": [...], "predict": false}'
```

With `predict: true` (the default) the service predicts as soon as the buffer holds enough history and raises alerts.

Response (HTTP 200):

```json
{
  "ingested": 3,
  "sites": {
    "CELL_006": {
      "status": "not_requested",
      "buffered_readings": 288,
      "required_readings": null,
      "assessment": null,
      "alerts": []
    }
  }
}
```

## Error: impossible value (422)

```bash
curl -X POST localhost:8000/predict -d '{... "latency_ms": -5 ...}'
```

The offending value is not echoed back; the field path tells you which reading to fix.

Response (HTTP 422):

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The request body or parameters are invalid.",
    "details": [
      {
        "field": "readings.3.latency_ms",
        "message": "Input should be greater than or equal to 0",
        "type": "greater_than_equal"
      }
    ]
  },
  "request_id": "4078a75eafdd"
}
```
